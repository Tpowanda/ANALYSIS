STEP 02 · AUTOMATION

SQL DATA MINING

These are the exact SQL queries that connect to Flex PLM and pull live data powering every KPI and chart. Copy any query and run it with your DBA.

⚠️ SAFETY RULES: Only use SELECT statements. Never write, edit, or delete data. Work with your DBA or IT team. Test on staging first — NEVER on production Flex PLM.
QUERY 1 — MILESTONE PASS/FAIL
Feeds: Data table · Schedule variance chart
-- Pull Pass/Fail results for Task 22 series SELECT t.task_code, t.task_name, a.scheduled_date, a.actual_date, a.approval_status, a.fail_rate_pct, a.actual_minutes, (a.actual_date - a.scheduled_date) AS variance_days FROM FLX_TASK t JOIN FLX_APPROVAL_STEP a ON a.task_id = t.task_id WHERE t.task_code LIKE '22%' ORDER BY a.scheduled_date;
→ FEEDS: On-Time Rate, Schedule Variance, Lead Time
QUERY 2 — ON-TIME RATE KPI
Feeds: Speedometer #1 · On-Time % display
-- Calculate Tasks On-Time Rate % SELECT COUNT(*) AS total_scheduled, SUM(CASE WHEN a.actual_date <= a.scheduled_date AND a.approval_status='PASS' THEN 1 ELSE 0 END) AS on_time_pass, ROUND( SUM(CASE WHEN a.actual_date <= a.scheduled_date AND a.approval_status='PASS' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1 ) AS on_time_rate_pct FROM FLX_APPROVAL_STEP a JOIN FLX_TASK t ON a.task_id = t.task_id WHERE t.task_code LIKE '22%';
→ FEEDS: On-Time Speedometer
QUERY 3 — HISTORICAL PASS RATE
Feeds: Probability tree · Go/No-Go decision
-- Historical pass rate → feeds probability tree SELECT t.task_code, COUNT(*) AS total_tests, SUM(CASE WHEN a.approval_status='PASS' THEN 1 ELSE 0 END) AS passes, ROUND( SUM(CASE WHEN a.approval_status='PASS' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 1 ) AS pass_rate_pct FROM FLX_APPROVAL_STEP a JOIN FLX_TASK t ON a.task_id = t.task_id WHERE a.actual_date >= ADD_MONTHS(SYSDATE, -24) GROUP BY t.task_code;
→ FEEDS: Probability tree pass/fail %
QUERY 4 — MONTHLY MANHOUR COST
Feeds: Manhour bar chart · Seasonal cost KPI
-- Monthly manhours by fabric type SELECT TO_CHAR(a.actual_date, 'MON YYYY') AS month, SUM(a.actual_minutes) AS total_minutes, ROUND( SUM(a.actual_minutes)/60,2 ) AS total_hours, ROUND( SUM(a.actual_minutes)/60*50,2 ) AS labor_cost_usd FROM FLX_APPROVAL_STEP a JOIN FLX_TASK t ON a.task_id = t.task_id JOIN FLX_STYLE_ATTR sa ON sa.style_id = t.style_id WHERE sa.attr_value LIKE '%RECYCLED%' GROUP BY TO_CHAR(a.actual_date, 'MON YYYY') ORDER BY MIN(a.actual_date);
→ FEEDS: Monthly bar chart · Cost KPI

ON-TIME RATE — FULL EXPLANATION
KPI #1 · SQL: FLX_APPROVAL_STEP · FLX_TASK

This KPI answers: "Of all tests we scheduled this season, what percentage were both approved AND finished on time?"

FORMULA: (PASS tasks where actual ≤ scheduled) ÷ COUNT(all tasks)
EXAMPLE: 4 on-time passes ÷ 6 total = 67%
WHY IT MATTERS: If this drops below 60%, social media calendar dates are at risk. SQL runs this nightly and alerts if threshold is breached.
TASK COMPLETION RATE — FULL EXPLANATION
KPI #2 · SQL: FLX_APPROVAL_STEP

Answers: "Have all scheduled tests actually been attempted?" — even a FAIL counts as complete because a decision was made.

KEY INSIGHT: 100% completion + low on-time rate means tests ARE happening but running late. SQL distinguishes these two scenarios automatically — very different risk profiles.
AVG FAIL PER STYLE — FULL EXPLANATION
KPI #3 · SQL: FLX_APPROVAL_STEP · FLX_STYLE

Tracks how many approval failures each style generates on average. Lower = better. Feeds the bell-curve regression and identifies which fabric types have the highest risk profiles.

USE CASE: If a new recycled material consistently scores above 0.5 fails/style, that's a red flag before the season starts. SQL shows this trend building in real time.
TASK EFFICIENCY RATE — FULL EXPLANATION
KPI #4 · SQL: FLX_TASK_ATTR · FLX_APPROVAL_STEP

Measures how many tasks get completed per minute of labor. A higher number means your team processes more approvals with less time. Declining efficiency signals capacity issues before they become delays.

UPDATED ORDER LEAD TIME — FULL EXPLANATION
KPI #7 · SQL: FLX_CALENDAR · FLX_MILESTONE · FLX_APPROVAL_STEP

The most critical KPI for social calendar alignment. Takes your original planned lead time and adds every accumulated day of schedule variance across all tasks.

FORMULA: Scheduled Lead Time ± SUM(variance_days)
Task 22: +3 + 2 + 3 = +8 accumulated days
If warehouse receipt was May 15 → now May 23
THE BOTTLENECK LINK: This is how a 3-day color test failure translates into a missed launch date. SQL makes this cascade visible before it's too late to act.
